## 为什么再写一份

市面上的 Java 面经大多是"题目 + 答案"。但 2026 年的面试官要的不是背答案的人——他要的是**知道这道题在考什么、还能往哪追问**的人。

所以每道题都是四段式：

| 段落 | 作用 |
| --- | --- |
| 难度 · 频次 · 标签 | L1 入门 / L2 进阶 / L3 深入，决定你复习的投入分配 |
| 参考答案要点 | 150–350 字，只留能写在白板上的干货，含具体参数值与阈值 |
| **考察意图** | 面试官想验证什么——背过八股，还是真实踩过坑 |
| **延伸追问** | 3–6 个连环追问，这才是真正被问倒的地方 |

## 关于第 11 章（这份资料最稀缺的部分）

2026 年 Java 岗位的 JD 里，Spring Boot、MySQL、Redis 仍是必考底座，但**溢价在 AI 工程层**。这一章 29 题全部从 Java 工程师视角写：

- **不是** Python AI 教程：每题都落到连接池、超时分层、背压、堆内存、虚拟线程
- 覆盖 Spring AI / LangChain4j、向量库选型（HNSW vs IVF_FLAT）、Rerank、RAGAS 评估
- Agent 死循环检测、分级预算硬止损、Prompt 注入防护
- 附真实 CVE 作为论据，而不是空谈"注意安全"

## 时效性

所有版本相关结论基于 **2026-09** 检索核实，不沿用旧口径：

- JDK：Java 26 最新（2026-03 GA），Java 25 为最新 LTS，Java 21 存量主流
- GC：CMS 于 JDK 14 移除；ZGC 自 JDK 23/24 默认分代；JDK 25 起 G1 全环境默认分代
- 虚拟线程：Java 21 转正（JEP 444），synchronized pinning 到 JDK 24（JEP 491）才解决
- Spring AI 2.0.0 GA（2026-06）／LangChain4j 1.19.x／MCP 规范 2026-07-28／A2A v1.0.0
- Kafka 4.0 起仅支持 KRaft；Redis 7.0 起 listpack 替代 ziplist

技术细节更新很快，发现过时或错误欢迎提 Issue / PR。
